## Restore database

Recommended: restore into a **new** database, verify, then switch the application.

```bash
gunzip -c /home/vdmc34/my/douyin-snapshots/2026-11-04/douyin_research.sql.gz \
  | docker exec -i dtk-postgres-1 psql -U dtk -d postgres \
      -c 'DROP DATABASE IF EXISTS douyin_research_restore;' \
      -c 'CREATE DATABASE douyin_research_restore;'

gunzip -c /home/vdmc34/my/douyin-snapshots/2026-11-04/douyin_research.sql.gz \
  | docker exec -i dtk-postgres-1 psql -U dtk -d douyin_research_restore
```

If you must restore the original `douyin_research`, stop writers first and take
another dump of the failed state before dropping anything. Never restore blindly
over the only copy.

```bash

```

Inspect the snapshot and the failed state before using `--delete`. If only a
subset broke, restore that subset instead of the whole tree.
